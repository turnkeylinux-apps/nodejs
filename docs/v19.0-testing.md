# Node.js 19.0 testing

## Scope and source decision

Node.js 19.0 uses Debian 13 Trixie packages for Node.js 20, npm and Nginx.
The inherited common profile temporarily uses the `n` version manager while
assembling the sample application. Product configuration removes that runtime,
the version manager and their files so the shipped `node` and `npm` commands
are owned by Debian packages.

PM2 and the Express/Pug sample application dependencies are not packaged by
Debian at suitable versions. They remain installed from the standard HTTPS npm
registry. npm supplies their maintained updater and records dependency
integrity hashes in the sample application's lock file. The source examples
remain Git checkouts with their HTTPS upstream remotes, so the `node` user can
update them with `git pull --ff-only`.

The `node` account's npm configuration uses the system CA bundle. This keeps
the inherited build-time npm installation and later administrator-initiated
npm updates on the appliance's managed trust path. The product overlay is also
registered through the existing common-overlay hook so this setting is present
before the inherited npm installation runs.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance nodejs \
    --source /home/agent/.local/worktrees/turnkey-apps/nodejs/wish-nodejs-v19-trixie
```

The command builds the Trixie root filesystem, imports the configured root
into Docker, boots the normal systemd and firstboot path, then runs
`tests/v19.sh`. The harness report is authoritative for the accepted source,
harness revision, archive and tree hashes, configured-root mode, installed
versions, runtime results, updater evidence, cleanup and verdict.

## Updater checks

`tests/v19.sh` runs `apt-get update`, confirms eligible Debian candidates for
`nodejs`, `npm` and `nginx`, and verifies the installed versions remain
unchanged. It also queries the PM2 candidate from npm without changing the
installed package. The documented PM2 command is
`npm install --global pm2@latest`; application dependencies use `npm update`.

`tests/v19-upgrade.sh` is a disposable Trixie fixture for the upstream
exception. It installs an older compatible PM2 and Express pair, starts a
sample HTTP application under PM2, updates both through npm, resurrects the
saved process, and verifies the same response after the upgrade. It also
checks the HTTPS registry and lock-file integrity fields.

The fixture was run with the application source mounted read-only:

```sh
docker run --rm --name tkl-nodejs-v19-upgrade \
    --mount type=bind,src=/home/agent/.local/worktrees/turnkey-apps/nodejs/wish-nodejs-v19-trixie,dst=/src,readonly \
    --mount type=bind,src=/usr/local/share/ca-certificates/microsandbox-ca.crt,dst=/usr/local/share/ca-certificates/microsandbox-ca.crt,readonly \
    debian:trixie-slim /src/tests/v19-upgrade.sh
```

It upgraded PM2 from `5.4.3` to `7.0.3` and Express from `4.20.0` to
`4.22.2`. PM2 resurrected the saved application, the HTTP response passed,
the registry used HTTPS, and all installed dependency entries in
`package-lock.json` retained integrity hashes.

## Known limitation

Docker runtime validation does not exercise the installer, kernel, bootloader
or physical hardware. Node.js adds no appliance-specific behavior at those
boundaries, so the validated Core 19 baseline supplies inherited evidence.

## Deferred issues

The shared Node.js profile downloads a temporary runtime through `n` while it
assembles the npm-managed application. Product configuration removes that
runtime and the version manager before the final filesystem is produced.
Moving the shared build itself to Debian Node.js would avoid the redundant
download for every inheriting appliance, but does not affect this appliance's
final runtime or updater path.
